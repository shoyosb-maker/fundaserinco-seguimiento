1. RESUMEN EJECUTIVO
=======================================================================

Se construyó desde cero una aplicación web de seguimiento personal con la
identidad visual de Fundaserinco. La aplicación funciona sin instalar nada:
se abre en el navegador y guarda todo localmente.

Incluye:
  · Tablero kanban con arrastrar y soltar.
  · Lista de tareas con filtros, orden y exportación.
  · Métricas calculadas en vivo.
  · Roadmap con hitos y carga mensual.
  · Calendario de reuniones propias (sin datos de ejemplo).
  · Biblioteca de repositorios con enlaces a los proyectos existentes.
  · Terminal de comandos real.
  · Integración opcional con Google Sheets (base de datos) y Google
    Calendar (eventos + enlace de Google Meet).
  · Ajustes con prueba de conexión, respaldo JSON y borrado de datos.

Decisiones de alcance acordadas:
  · NO se cargan reuniones ni tareas de ejemplo.
  · NO hay usuarios/autenticación en esta fase.
  · Primero debe funcionar; después se agregan usuarios y extras.
  · El proyecto quedará listo para publicarse en GitHub / GitHub Pages.

6. GOOGLE SHEETS COMO BACKEND
=======================================================================

6.1 Qué hace
  El archivo google-apps-script/Code.gs convierte una hoja de cálculo en
  una API JSON. La app web estática llama a esa API con fetch.

  Hojas creadas automáticamente:
    Tareas     · id, title, description, status, priority, points,
                 assignee, tags, due, created, updated, completedAt,
                 repoIds
    Reuniones  · id, title, date, start, duration, category, attendees,
                 notes, meetLink, eventLink, eventId, source, created,
                 updated
    Hitos      · id, title, date, status, description, created, updated
    Repositorios · id, name, url, description, tags, status, source,
                   created, updated

  Los repositorios usan la misma sincronización por id y fecha que las
  tareas: se envían al guardar, se borran en Google al eliminar y se
  mezclan al descargar.

6.2 Contrato de la API
  Todas las peticiones exigen un token.

  GET  <url>/exec?token=TOKEN&action=ping
  GET  <url>/exec?token=TOKEN&action=list

  POST <url>/exec        (Content-Type: text/plain;charset=utf-8)
  Body:
    {
      "token": "TOKEN",
      "action": "upsertTask",
      "data": { ... }
    }

  Acciones POST:
    ping                 Verifica credenciales y devuelve datos de la hoja.
    list                 Devuelve { tasks, meetings, milestones, repos }.
    upsertTask           Inserta o actualiza una tarea por id.
    deleteTask           Elimina por id.
    upsertMeeting        Guarda reunión; con createMeet=true crea el evento
                         y el Meet.
    deleteMeeting        Elimina fila y, si existe, el evento de Calendar.
    upsertMilestone      Inserta o actualiza un hito.
    deleteMilestone      Elimina un hito.
    upsertRepo           Inserta o actualiza un repositorio por id.
    deleteRepo           Elimina un repositorio por id.
    bulkUpsert           Inserta/actualiza listas completas (sincronización).
    importCalendar       Devuelve eventos del calendario en un rango.

  Respuesta:
    { "ok": true, "data": ... }
    { "ok": false, "error": "mensaje" }

  Se usa Content-Type text/plain para evitar el preflight CORS, que
  Apps Script no responde.

6.3 Instalación paso a paso
  1. Crear una hoja de cálculo nueva en Google Sheets.
  2. Menú Extensiones → Apps Script.
  3. Borrar el contenido de Code.gs y pegar google-apps-script/Code.gs.
  4. Abrir Configuración del proyecto → activar "Mostrar archivo de
     manifiesto appsscript.json" y pegar google-apps-script/appsscript.json.
     Esto habilita el servicio avanzado Google Calendar API.
  5. Guardar y ejecutar la función "instalar" una vez.
     Autorizar los permisos solicitados.
     En el registro de ejecución aparecerá:
        TOKEN: xxxxxxxxxxxxxxxxxxxxxxxxxxxx
     Copiar ese valor.
  6. Implementar → Nueva implementación → Aplicación web:
        Ejecutar como: yo
        Quién tiene acceso: cualquier persona
     Implementar y copiar la URL que termina en /exec.
  7. En la aplicación: Ajustes → Conexión con Google.
        URL del Web App: <url /exec>
        Token: <token copiado>
        Calendario: primary
        Zona horaria: America/Bogota (o la que corresponda)
     Guardar y pulsar "Probar conexión".
  8. Probar una tarea, una reunión y un repositorio; revisar que
     aparezcan en las hojas Tareas, Reuniones y Repositorios.

  Nota: cada vez que se modifique Code.gs hay que crear una nueva versión
  de la implementación (Administrar implementaciones → Editar → Nueva
  versión) o implementar de nuevo. Al actualizar desde v0.2.x hay que
  ejecutar `instalar` otra vez para crear la hoja Repositorios; la URL
  /exec se conserva si se edita la implementación existente.

6.4 Seguridad
  · El token vive en Propiedades del script (API_TOKEN) y en el
    localStorage del navegador y/o en js/local-config.js (ignorado).
    Nunca está en archivos versionados.
  · Cualquiera que tenga la URL /exec y el token puede leer/escribir la
    hoja. Tratarlo como una contraseña.
  · No se debe publicar el token en GitHub ni en capturas.
  · El acceso "cualquier persona" es necesario para que la web estática
    pueda llamar al Web App. No es lo mismo que la hoja sea pública: la
    hoja sigue privada; la API exige token.

6.5 Configuración local de credenciales (predeterminados)
  · js/local-config.js contiene apiUrl, token, calendarId, timezone y
    meetByDefault. Está incluido en .gitignore.
  · js/local-config.example.js es la plantilla versionada y vacía.
  · config.js fusiona en este orden:
        DEFAULTS  ->  FS_LOCAL_SETTINGS  ->  ajustes guardados
    Por lo tanto, lo que se guarde desde Ajustes siempre gana.
  · index.html carga js/local-config.js antes de config.js. Si el
    archivo no existe en un clon, la app sigue en modo local.
  · En GitHub Pages el archivo no se publica; se configura una vez en
    Ajustes por navegador.
  · Verificación: ping y list reales con la hoja activa; los datos de
    prueba locales se limpiaron y no se enviaron registros falsos.

7. GOOGLE CALENDAR Y GOOGLE MEET
=======================================================================

7.1 Creación automática
  Cuando se guarda una reunión con Google conectado y la casilla de Meet
  activa, el backend:
    1. Convierte fecha/hora de la zona configurada al formato de Calendar.
    2. Crea el evento con los invitados indicados.
    3. Solicita una conferencia de tipo hangoutsMeet mediante
       conferenceData.createRequest.
    4. Devuelve y guarda eventId, eventLink y meetLink.
    5. Envía la invitación a los correos (sendUpdates: all).

  Esto usa el servicio avanzado "Google Calendar API v3", habilitado por
  appsscript.json. Sin ese servicio, el backend crea el evento con
  CalendarApp pero sin Meet, y devuelve una advertencia visible en la app.

7.2 Edición y borrado
  · Editar una reunión con eventId actualiza el evento (patch) sin crear
    uno nuevo.
  · Eliminar la reunión intenta borrar el evento de Calendar primero.
  · Si la API avanzada falla, se usa CalendarApp como respaldo.

7.3 Modo sin Google
  · La reunión se guarda localmente.
  · El modal ofrece:
       - Abrir plantilla de Calendar (evento con título, fecha, detalles
         e invitados; sin Meet automático).
       - Crear Meet ahora (abre https://meet.google.com/new).
  · El enlace de Meet generado manualmente se puede pegar en el campo
    "Enlace de Meet" y se guarda en la reunión.
  · La agenda muestra la etiqueta "Meet" y el botón para abrirlo.

7.4 Importar desde Google Calendar

8. SINCRONIZACIÓN
=======================================================================

  Estrategia: local-first.
  · Toda acción se guarda primero en localStorage.
  · Si Google está conectado, se envía en segundo plano.
  · Si el envío falla, el dato queda local y se muestra una advertencia.
  · Descargar de Google:
      1. list → descarga tareas, reuniones, hitos y repositorios.
      2. Merge por id; gana el registro con "updated" más reciente.
      3. No envía nada a la hoja.
  · Subir a Google:
      1. bulkUpsert con el estado local completo (incluidos repositorios).
      2. Pide confirmación y muestra el conteo enviado.
      3. No borra filas que no estén en la app.
      4. Guarda la fecha de última sincronización.
  · Los repositorios usan upsertRepo/deleteRepo al crear, editar o
    borrar, igual que tareas e hitos.
  · El comando sync de la terminal hace descarga + subida.
  · Los borrados hechos desde la app se envían al backend. Si alguien
    borra una fila directamente en Sheets, una descarga puede volver a
    crearla desde la copia local.
  · No hay resolución de conflictos avanzada ni tombstones. Para uso
    personal de un solo dispositivo es suficiente.

11. LIMITACIONES CONOCIDAS
=======================================================================

  · No hay usuarios ni permisos: es una herramienta personal.
  · Los datos locales viven en un solo navegador; para otro equipo hay
    que sincronizar o importar el JSON.
  · El token de Google se guarda en localStorage. Es aceptable para uso
    personal; para multiusuario se debe migrar a OAuth.
  · La sincronización es aditiva; no maneja eliminaciones externas.
  · Meet automático depende del servicio avanzado Calendar API.
  · Los eventos de día completo y los enlaces de Meet existentes no se
    importan.
  · Las reuniones recurrentes importadas comparten eventId.
  · No hay recordatorios, notificaciones ni envío de correos propio.
  · El almacenamiento del navegador ronda los 5 MB.
  · Probado en Chromium; falta validar Safari y Firefox.
  · Los campos de fecha usan el formato del navegador.
  · Sin service worker: requiere conexión para cargar fuentes de Google
    (los estilos y el sistema de fuentes tienen fallback).

14. SOLUCIÓN DE PROBLEMAS
=======================================================================

  "Token inválido"
    · El token de Ajustes no coincide con API_TOKEN en Propiedades del
      script. Volver a ejecutar instalar o copiar el token del registro.

  "La URL respondió algo distinto a JSON"
    · La implementación no está publicada con acceso "cualquier
      persona", o la URL no termina en /exec.
    · Volver a implementar y copiar la URL correcta.

  "Failed to fetch"
    · URL equivocada, sin conexión o el Web App no está desplegado.
    · Probar primero ping desde Ajustes y revisar la implementación.

  No se crea el Meet
    · Falta el servicio avanzado Google Calendar API. Habilitarlo en
      Apps Script → Servicios, o revisar appsscript.json.
    · El evento se crea igual, pero sin Meet; la app muestra la
      advertencia y permite pegar un enlace manual.

  El evento queda en otra hora
    · Revisar la zona horaria en Ajustes y la del calendario de Google.
    · El valor por defecto es America/Bogota.

  Los datos no aparecen en otro navegador
    · Son locales. Sincronizar con Google o importar el JSON.

  La app no recuerda el tema o los datos
    · El navegador puede estar bloqueando localStorage (modo privado o
      políticas). Probar en una ventana normal.

  Cambié Code.gs y no se refleja
    · Crear una nueva versión de la implementación.
